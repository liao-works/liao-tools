# 运单轨迹查询

把一批运单号粘贴进来，通过 17TRACK 开放接口一次性查出每票的承运商、当前状态、最新轨迹事件和预计送达日期，结果可以导出为 Excel。查询需要自备 17TRACK 的 API Key（官网免费申请，新注册账号有 100 单免费测试额度）。

## 在哪里找到入口

- 打开应用后，点击左侧边栏「业务查询」分组中的「运单轨迹」。
- 也可以在工作台点击「运单轨迹」卡片（卡片说明为「批量轨迹查询与预计送达」）。
- 在「船司查询」的「货物追踪」页签里点「去运单轨迹查询」或「在运单轨迹中查询」，会直接跳到本页并把单号带入「运单号列表」。

![运单轨迹查询页：上方是「接口设置」卡片，下方是「批量查询」卡片](/images/tracking/01-overview.png)

## 逐步操作

### 第一次使用：配置 API Key

页面顶部的「接口设置」卡片里列出了三步指引，照着做即可：

1. 点击指引第 1 步中的「17TRACK 开放平台」链接，系统浏览器会打开 17TRACK 的 API 申请页，在这里注册账号并开通 API 服务（免费）。
2. 登录 17TRACK 的 API 控制台，在「设置 → 访问密钥」页复制密钥（即 17token）。对接口用法有疑问时，可点击指引第 2 步中的「接口开发文档」链接查阅官方文档。
3. 回到应用，把密钥粘贴进「API Key（17token）」输入框（输入内容以圆点显示），点击「保存」。
4. 保存成功后会弹出「已保存」提示。密钥只保存在本机，不会上传到其他服务器；下次打开应用时会自动带出，无需重新填写。

输入框下方还有一行关于额度的说明：额度按注册单号计费，已注册过的单号重复查询不会重复计费（以官方计费规则为准）。

### 批量查询运单号

1. 在「批量查询」卡片的「运单号列表」输入框中粘贴单号。换行、逗号、分号、空格（含中文逗号、分号）都能作分隔，从 Excel 里整列复制过来也可以。
2. 粘贴后，输入框下方会实时显示「共 N 个单号，将分 X 批查询」：重复单号自动去重，每 40 票为一批。
3. 点击「开始查询」按钮。按钮会变为「查询中…」并出现进度条和百分比，随批次完成逐步前进。
4. 查询结束后弹出「查询完成」提示，说明成功与失败各多少票，页面下方出现「查询结果」卡片。

应用会先把单号在 17TRACK 注册、再逐批查询轨迹（这是 17TRACK 接口要求的流程），每批之间自动限速。刚交寄的单号 17TRACK 可能还没采集到轨迹，这类单号会在「查询备注」列提示稍后重试。

### 阅读查询结果

![批量查询结果：表格列出运单号、承运商、状态、最新事件、运输天数、预计送达与查询备注（图中轨迹为演示数据，实际以 17TRACK 返回为准）](/images/tracking/02-batch-result.png)

「查询结果」卡片标题下显示「成功 N 票 · 失败 N 票」的汇总。表格共七列：

- **运单号**：你查询的单号。
- **承运商**：17TRACK 识别出的承运商名称；一家单号可能有多家承运商承接（如「中国邮政 / Royal Mail」），无法识别时显示「—」。
- **状态**：17TRACK 的里程碑状态，显示为中文——已收录信息、运输中、派送中、待取件、已签收、派送失败、异常、包裹过期、未查到轨迹；未收录的状态显示原文。「已签收」为绿色，「异常」「派送失败」为红色，状态下方的灰色小字是子状态。
- **最新事件**：最近一条轨迹的描述，下方小字是发生时间和地点。
- **运输天数**：从收寄到当前的运输天数，未产生时显示「—」。
- **预计送达**：17TRACK 估计的送达日期，可能是区间（如 `2026-10-28 ~ 2026-11-02`），也可能只有单个日期或「—」。
- **查询备注**：该单号查不到轨迹时的原因说明（如「尚未注册或轨迹仍在采集，请稍后重试」「今日查询额度已用尽」），全部成功时此列为空。

有失败单号时，表格上方会出现一条黄色提示：「部分单号未获取到轨迹，原因见「查询备注」列；额度耗尽或 Key 无效时请处理后重试。」

### 导出 Excel

1. 点击「查询结果」卡片右上角的「导出 Excel」按钮，会弹出系统保存对话框，默认文件名为 `轨迹查询结果_日期.xlsx`。
2. 选好位置保存后，应用弹出「导出完成」对话框，点「打开文件」用系统默认程序打开表格，或点「复制路径」把文件路径复制到剪贴板。

导出的 Excel 比页面表格多三列：子状态、最新事件时间、位置单独成列，便于筛选和统计。

## 小技巧

- 修改「运单号列表」的内容后，上一次的查询结果会被清空，需要重新点「开始查询」。
- 只查几票时也走同一套流程；单号超过 40 票时应用自动分批并限速，不需要手动拆分。
- 「已签收」「异常」等状态由 17TRACK 聚合而来，可能存在同步延迟；异常件与派送失败请以承运商官网为准。
- 在 17TRACK 控制台更换密钥后，新密钥最长 5 分钟生效、旧密钥立即失效；换完记得回应用里粘贴新 Key 并点「保存」。
- 手头有快递单号但不知道是哪家承运商时，可以直接扔进本页批量查询，17TRACK 会自动识别。

## 常见问题

**问：提示「API Key 无效或未授权（-18010002）」怎么办？**

答：说明 17TRACK 不认可当前密钥。先去 API 控制台的「设置 → 访问密钥」页核对是否复制完整；刚更换过的密钥最长要 5 分钟才生效。确认无误后回应用里重新粘贴并点「保存」，再点「开始查询」。

**问：「查询备注」显示「尚未注册或轨迹仍在采集，请稍后重试」？**

答：17TRACK 还没有采集到这票的轨迹，常见于刚交寄的单号。过一段时间重查即可，重复查询已注册过的单号不会重复计费。

**问：提示「今日查询额度已用尽」或「API 额度已耗尽」？**

答：当日免费额度或账户额度用完了。可以到 17TRACK 官网充值，或次日再试；具体计费规则以官方说明为准。

**问：「查询备注」显示「承运商无法自动识别」？**

答：17TRACK 未能根据单号自动判断承运商。可以到 17TRACK 官网手动查询该单号并指定承运商，之后回本页重查。

**问：导出的 Excel 和页面表格列不一样？**

答：导出文件把页面合并显示的内容拆成了独立列（子状态、最新事件时间、位置），其余列与页面一致，方便在 Excel 里筛选。
