# R4 Windows 桌面验收候选：数据完整性与实机复核

本阶段基于 #11。主要目的是把可以自动执行的 Rust 存储回归测试与真实 Windows 安装包工件接通，避免仅凭 TypeScript 构建和 Rust `cargo check` 宣布最终验收成功。

## 已修正的存储行为

- **损坏的任务数据不再变成空列表**：原来的 `load_sticky_notes` 对反序列化错误使用 `unwrap_or_default()`，导致坏数据看起来与“用户从未创建任务”一样。现在只有存储键缺失才采用空任务列表或默认配置；已有键无法解码时返回错误，禁止继续覆盖。
- **损坏的配置不会被静默重置**：包括小组件布局和置顶操作，若原配置存在但损坏，则明确返回错误，不再把默认设置写回替换已保存数据。
- **磁盘写入失败后的进程内回滚**：Rust `save_sticky_notes` 和纯配置更新保存前留存四个或两个旧键值；如果 `store.save()` 报错，就还原进程内任务、配置、版本与修订号的旧值。该行为避免后续窗口从内存读取到“失败但看起来已保存”的数据，**不保证异常断电或磁盘损坏后的文件级恢复**。
- **并发修订号回归测试**：旧快照不得覆盖新修订号；旧格式没有 `revision` 时按 0 兼容；修订号溢出和坏任务数据显式拒绝。
- **保留 #11 的跨窗口冲突拒绝**：仍不自动合并两个冲突操作，避免损失最后一个编辑者没有看过的数据。

## GitHub Actions 产物

已有的 `.github/workflows/r4-desktop-check.yml` 继续执行前端构建和 Tauri 二进制命令编译，并补充：

1. `cargo test --locked --manifest-path src-tauri/Cargo.toml --lib sticky_notes::todo_store_integrity_tests -- --nocapture`，只运行真正对应此次修复的测试。
2. `pnpm tauri build --bundles nsis`，生成 Windows NSIS 安装程序。
3. `actions/upload-artifact@v4`，上传 `liao-tools-r4-windows-acceptance` 工件（保留 7 天）。

从最新 PR 的 **Checks → R4 Windows desktop compile** 打开运行记录，进入 **Artifacts** 下载候选安装包。该包是**未签名的验收版本**，只能用于可信 Windows 测试设备，不应误认为正式发布或可安全无提示分发。

## 必须在真实 Windows 桌面验证

| 检查场景 | 实机操作 | 通过条件 |
|---|---|---|
| 启动和切换路由 | 安装候选包，启动，进入关税、Alta、Excel、UPS/DPD、系统工具、Todo、设置 | 无程序崩溃、白屏和无法操作的主按钮 |
| Todo 多窗口新增 | 打开 Todo 和桌面小组件，在两个窗口几乎同时分别新增任务 | 两项任务都在最终列表，冲突一方提示同步后重试，而不是静默丢任务 |
| Todo 旧快照覆盖 | 一个窗口先读旧列表；另一个完成任务后，第一个立即编辑/删除 | 后写入旧修订号时明确冲突，已有新状态不被覆盖 |
| Todo 存储失败 | 在可控测试环境下使数据文件不可写，然后保存任务 | 失败可见、旧任务保留；恢复可写后重试，关闭重启保持一致 |
| Todo 损坏恢复 | 先完整备份小组件存储数据文件，再故意写入错误 JSON 结构 | 显示读取错误，不自动变成空任务后覆盖原存储；还原备份后重新读取正常 |
| Todo 布局设置 | 移动和改变小组件尺寸，置顶、桌面模式后重开 | 布局和置顶状态持久化且不会覆盖主窗口新增任务 |
| 自定义系统工具 | 创建测试命令，启动成功/失败，禁用后重新启用 | 失败启动不计次数；工具和工作目录不丢失；真实失败提示 |
| 文件功能 | 用小体量真实 XLSX 分别执行 Excel 拆分与 UPS、DPD | 输出文件路径真实存在，可被 Excel 打开且内容符合源数据 |
| 关税 GB/NI | 真实数据精确查询、NI 审查预览、离线情况 | 明确数据来源与版本，无未验证税率当成生效税率 |
| Alta / Amazon | 真实数据源正常与不可用两种状态 | 正常结果来源明确；失败不输出虚假成功 |
| 应用更新 | 检查更新、下载失败、静默安装结果 | “命令已启动”和“确认完成”区分准确，失败不误报安装成功 |

**验收结论：** 代码级检查完成与安装包生成只是进入 GUI 手动验收的前提。上述真实桌面步骤尚未执行前，各 R4 PR 保持 Draft、不合并到 `master`、不发布正式版本。若安装包构建失败，应直接查看对应 Action 日志修复，而非将候选工件视为已生成。
