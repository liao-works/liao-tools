# R4 集成回归与发布验收

本变更堆叠在 #8 后，延续 #4 → #5 → #6 → #7 → #8 的代码。目标是**验证实际接线、处理异常、保留数据边界**，而非添加装饰性的二次校验。

## 已由 GitHub Actions 验证的基础

在 2026-10-15 检查时，PR #4～#8 的 TypeScript + Vite 前端构建全部成功；PR #5 和 #8 的 Windows Rust 关税快照测试通过。Rust 检查具体覆盖 downloader、preview、signed、ni_review 子模块，并不等同于 GUI 实机测试。

集成分支另外新增 \`.github/workflows/r4-desktop-check.yml\`：在 Windows runner 编译完整 Tauri 桌面入口和命令注册（\`cargo check --locked --manifest-path src-tauri/Cargo.toml --bin liao-tools\`，包含生成生产前端资源）。这个检查验证编译和命令接线，但**不能证明 Windows GUI 或真实外部网站可用**。

## 修复的实际回归风险

- **应用安装**：处理 \`install-complete\` 事件的成功、失败与不需要重启三种分支，解决失败后一直显示“安装中”和事件监听未释放的问题。安装命令返回不等同于安装已成功；防止重复提交。
- **Todo 小组件**：保存失败会显示真实错误；新增/勾选/删除/编辑任务在本地持久化成功后才更新视图，失败保留输入和旧任务供重试。普通 Tab 焦点与交互控件 Enter 不再被全局键盘快捷键抢占。
- **Tauri 事件生命周期**：应用 Todo 入口和小组件移动/数据监听异步注册时，组件卸载后能正确清除，防止反复打开后监听重复。
- **自定义工具管理的前后端契约**：修复 Rust `get_all_tools` 仅返回 `enabled=1` 工具导致禁用后无法再启用的问题；同时返回真实 `working_directory`，避免进入编辑页后丢失启动工作目录。保留 `enabled` 字段，系统工具仍不能禁用。

## 仍需真实桌面端的最终验收

| 场景 | 验收标准 | 当前结论 |
|---|---|---|
| Windows Tauri 启动 | 窗口正常显示、无启动时 Rust panic | 待 GUI 实机 |
| 窄窗口与深浅色 | 1024px 宽可操作，各页无被遮住的主操作按钮，R4 tokens 有效 | 待 GUI 实机 |
| 关税 GB/NI 查询 | 精确/模糊/批量与真实性状态，下载成功/失败及影子隔离 | 待 GUI + 真实数据 |
| Alta 禁运 | 清单为空、联网失败、命中/未命中、批量导出 | 待 GUI + 真实数据 |
| Excel 拆分 | 三模式真实输入/输出，按预期生成文件，能打开输出 | 待桌面真实文件 |
| UPS/DPD | 主文件、可选明细、两套模板及自定义模板 | 待桌面真实文件 |
| Amazon 商品 | 16 站点可选、真实进度、导出，跨站点结果不混用 | 待实际外部接口 |
| 系统工具 | 启动、键盘焦点、禁用后重新启用、自定义工作目录不丢失、最近记录 | 待桌面真实程序 |
| Todo 主窗口和小组件 | 新增/编辑/完成/删除、保存失败、置顶、关闭重开后数据一致 | 待 GUI + 本地存储 |
| 应用更新 | 下载失败、安装命令返回、\`install-complete\` 成功失败、重启 | 待桌面真实安装 |
| 更新历史 | 列表和明细读取，数据库异常时错误可见 | 待 GUI |
| macOS | Tauri 打包、程序启动及文件权限行为 | 待 macOS 实机 |

发布标准：Windows GUI 关键业务流程测试完成、无数据误报/覆盖、原有 Tauri 命令语义不变、受影响 CI 通过，才能解除各个堆叠 PR 的 Draft 状态，并按 #4 → #9 顺序合并。不通过编译来冒充桌面 E2E。

## 不做的工作

不增加业务侧重复 preflight，不制造假百分比，不修改签名校验或真实税率发布边界，不将前端 toast 当作后端持久化成功。
