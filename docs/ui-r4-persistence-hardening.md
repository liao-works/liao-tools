# R4 第七阶段：桌面写入一致性与工具启动事实

基于 #9 的 `ui/redesign-r4-integration`，补齐上一轮编译检查无法覆盖的真实数据一致性风险，不更改税率采集、Alta 匹配和其他业务算法。

## 已修复

- 主窗口 Todo：`addTask`、`updateTask`、`deleteTask`、`toggleTask`、`clearCompleted`、`updateConfig` 统一从**最新 Zustand 状态**构造写入内容，在写入 `save_sticky_notes` 成功后才更新前端状态，不再把保存失败伪装为本地任务已改变。
- 主窗口所有 Todo 写入在单窗口中**串行提交**，避免快速编辑/完成/删除时多个旧快照以不同顺序落盘；收到 Tauri 数据更新事件后，先等本窗口写入队列结束，再重新读取持久化数据。
- 添加任务的提交按钮在写入过程中禁用，避免重复点击；编辑保存失败保留输入状态；删除/完成/清空失败不产生未处理的 Promise 异常。保存失败详情由已有 Todo store 的 `error` 显示。
- Todo 设置弹窗：主题/颜色/尺寸、快捷键与透明度存储失败时，弹窗内也显示持久化错误，避免异步事件无错误处理。
- Rust 自定义工具启动：**先调用实际的 `launch_program`，成功后才更新启动次数和“最近使用”**。若程序已启动但统计数据库写入失败，仅记录日志，不把已启动的程序错误地报告为启动失败。
- Rust 自定义工具列表：`get_all_tools` 若读取数据库失败，会返回真实数据库错误而非悄悄退化成只有系统工具；前端显示加载失败与重试，不把用户保存过的工具伪装成不存在。

## 验证范围

- `pnpm install --frozen-lockfile && pnpm build`。
- 新增于 #9 的 Windows Tauri 完整入口 `cargo check --locked --manifest-path src-tauri/Cargo.toml --bin liao-tools`，覆盖此处 Rust 命令编译。
- 人工桌面回归：Todo 连续快速新增/编辑/切换完成/删除；写入失败后仍能重试；在主窗口与小组件间同步任务；工具启动成功与失败的最近记录/次数区别。
- 受多个窗口独立并发修改同一份 Todo 数据的情况，仍需实际 Tauri 联调验证；当前顺序保证作用于主窗口单一 Zustand 实例，**不是跨进程/跨窗口的事务声明**。
- Windows/macOS GUI 实机与数据库受损情形仍未执行，不应声称生产验收通过。

不添加虚假状态、无意义校验、占位数据或估计的查询进度。
