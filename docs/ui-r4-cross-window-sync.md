# R4 第八阶段：跨窗口 Todo 冲突保护

本阶段基于 \`ui/redesign-r4-persistence-hardening\`（#10），针对 Todo 主窗口和独立悬浮小组件同时读写同一份持久化数据的真实覆盖风险。

## 实现

- Rust \`TodoStoreData\` 新增 \`revision\` 字段（从旧存储读取时默认为 \`0\`）。\`version: 1\` 仍然是旧有的**数据结构版本**，不是写入修订号。
- \`load_sticky_notes\` 在共享 Rust \`TODO_STORAGE_LOCK\` 下读取完整任务、配置、版本和修订号，避免读取到正在写入的一半状态。
- \`save_sticky_notes\` 在相同锁下核对客户端的 \`revision\` 和目前存储的修订号；过期快照返回明确冲突异常；匹配才写入任务、配置和修订号 \`+1\`，保存成功后发出既有同步事件并返回新修订号。
- 小组件移动/尺寸写入以及快捷键置顶改变同样使用 Rust 锁和修订号，避免配置修改和整份 Todo 保存彼此静默覆盖。
- Todo 主窗口原有顺序写队列保留，提交前读取当前已持久化修订号，成功后更新修订号；发生冲突时读取新数据、显示真实错误，保留新增/编辑输入用于重试。
- Todo 小组件新增修订号状态、保存期互斥和冲突后的数据同步。挂起的外部事件会在本地写操作完成后同步，避免把异步事件误当作当前保存已成功。错误提示可主动执行“同步最新数据”。
- 不自动重放过期快照的删除或覆盖操作，避免“自动重试”再次改掉用户未见过的最新数据。

## 明确的验证边界

- Windows CI：\`pnpm build\` 与 \`cargo check --locked --manifest-path src-tauri/Cargo.toml --bin liao-tools\`。该检查确认 Rust 命令和两个 React 窗口的类型契约可以编译，**不等于真实 GUI 已完成验收**。
- 桌面实机必验：主窗口和小组件同时新增不同任务；一个窗口使用旧列表修改同条任务；快速拖动小组件后编辑任务；任务保存失败再同步；关闭重新打开后任务、窗口状态仍一致。
- 本阶段实现的是**检测并拒绝过期快照**（乐观并发控制），不是把所有编辑自动合并。发生冲突必须让操作者确认后重试。
- \`tauri-plugin-store\` 写入错误仍由原有命令返回；异常断电与跨进程崩溃恢复不在本阶段保证范围。
- 不修改 GB/NI 关税、Alta、Amazon、Excel 等业务命令，不增加额外无意义预校验或模拟进度。
