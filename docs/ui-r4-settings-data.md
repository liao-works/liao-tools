# R4 第五阶段：偏好设置与数据维护

本阶段基于 \`ui/redesign-r4-productivity\`（第四阶段），**不修改关税采集/核验发布流程及 Alta Rust 业务更新算法**。

## 设置页

- 保留已有深色/浅色/跟随系统及主题选择。
- 真正的应用自动检查版本选项改用 \`load_update_settings\` 和 \`save_update_settings\`，与应用启动时的检查共用同一配置。开关只在保存成功后更新 UI 状态。
- **应用更新与业务数据更新是两个不同系统**：页面明确说明应用版本检查不会自动下载最新关税/禁运数据库。
- 移除没有实际消费者的独立前端 \`autoUpdate\`、\`notifications\`、\`saveHistory\` 表单开关，以及没有动作的“反馈/官网”按钮；未删除兼容用的历史存储文件。
- 项目仓库是真正的外部链接；保留独立的应用版本检查对话框。

## 统一数据维护

- 增加 \`/data-maintenance\`，侧边栏、首页及全局搜索中均可找到。
- 可在 GB/NI 关税和 Alta 禁运模块间切换，并保留 \`?module=tax\` / \`?module=alta\` 直接链接。
- 直接复用既有 \`UpdateTab\` 和 \`DataManageTab\`，不复制业务状态或发明采集命令，原 \`/tax\` 和 \`/alta\` 内的旧标签仍保持可用。
- 关税页打开时只读取本地版本；远程更新检查由用户明确触发，避免每次进页重复请求。
- 关税正式更新须等 Rust 后端返回 \`true\` 才显示成功；返回 \`false\`/异常不当作安装成功；成功后清理过期远程比对、读取新本地版本。
- GB/NI 核验状态与 NI Other 证据边界不变；影子预览与签名审核保留且归入高级区域，不作为正常更新的强制额外步骤。
- Alta 本地信息查询与更新分别显示真实失败；\`updateDatabase().success=false\` 不能误报“更新成功”，读取状态失败不冒充数据库为空。
- 更新历史列表/详情获取失败时给出实际异常，避免未处理 Promise rejection。
- 应用安装包下载对话框去除“仅隐藏 UI，后台仍然下载”的伪取消按钮，并确保进度事件监听解除。

## 需要的验收

1. \`pnpm install --frozen-lockfile && pnpm build\`。
2. 设置页外观与 app \`auto_check\` 保存/失败场景；MainLayout 下次启动使用同一设置。
3. 新数据维护路由与两条深链、切换模块、查询返回。
4. 关税仅手动远程检查、离线只显示本地状态、\`tax_download_update\` true/false/throw 分流。
5. Alta 更新成功/失败与状态读取失败、历史列表/详情拒绝后的 UI。
6. 高级审计不能自动写入正式关税库。
7. Windows/macOS 真实 Tauri 应用与实际数据库的运行、更新、文件对话框及暗色适配仍需后续端到端回归。

**不提供并未实现的实时官网增量触发、定期全量刷新、通知与审计完整性保证**；这些需由真实采集/更新后端提供，而不是 UI 开关。
